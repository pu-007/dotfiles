# WOTS 的 Rust 设计哲学 / Rust Design Philosophy

> 为什么 wots 长成现在这个样子——给未来维护者的设计决策记录。

---

## 1. 类型即文档，match 即安全网

整个工具的核心是 `PkgType` 六个变体。所有类型相关行为（目标路径、是否用
stow、是否拷贝、是否 sudo）都是枚举上的方法，而不是散落各处的 if/else 字符串
判断。新增/删除变体时，编译器逐点列出所有需要修改的位置——本次移除三个类型、
新增一个类型的重构能在半小时内完成且测试全绿，正是这个设计带来的。

**原则：让非法状态不可表示。** `"winlocal"` 这类字符串在 v2.0 之后无法再被
构造成 `PkgType`，相关 bug 在编译期就被消灭。

## 2. 单二进制，零运行时依赖

dotfile 管理工具的部署环境往往就是"刚装好系统的 WSL"。Python 版需要解释器
和虚拟环境；Rust 静态二进制（~1.7 MB）cp 过去就能跑。依赖清单里全部是纯
Rust crate（无 C 绑定风险，blake3 有 asm 但可选），交叉编译友好。

外部进程只依赖三样：`stow`、`robocopy.exe`、`pwsh.exe`——且全部有降级路径。

## 3. LazyLock 全局配置，而非配置对象

`config.rs` 用 `std::sync::LazyLock` 把环境变量读取收敛为一组全局量。理由：

- CLI 工具生命周期短，全局可变状态没有并发危害；
- `main.rs` 在任何 LazyLock 求值前把 `--win-user` 写回环境变量，
  保证"CLI 参数覆盖 env"只写一处；
- 避免 Config 结构体在十几个模块间传来传去（线程安全共享又要 Arc 包一层）。

代价是测试中不能按用例改配置——所以路径类测试都设计为不依赖具体 HOME 值，
或在断言里守卫环境变量未设置。

## 4. 原子性优先

- move = copy 到 `.wots_tmp_<pid>` → 数量/大小校验 → rename → 删源；
- 索引写入 = `.tmp` → rename；
- 元数据备份（pacman/npm 列表）同样走 `.tmp` 中转。

文件管理工具最怕"改到一半留下半成品"，宁可多一次全量校验也不做原地覆写。

## 5. 缓存 + 快速路径，但不信任缓存

blake3 全量哈希在大仓库上很贵，于是有 `.wots_index.json`：mtime+size 未变的
已同步文件直接走快速路径。但缓存永远只是优化：

- 解析失败 → 告警并重建，绝不 panic；
- 反向扫描会清理指向已消失文件的陈旧条目；
- 状态判定的最终依据始终是当前文件系统，索引毒化有集成测试回归保护。

## 6. 并发用 rayon，粒度是"文件"

Windows 拷贝的瓶颈在跨 9p 文件系统的 IO 等待，rayon 线程池（默认 8）按文件
并行即可吃满收益，不需要 async。刻意不引入 tokio：单机批处理任务，async 的
复杂度换不来可感知的收益。

## 7. 错误处理：anyhow + 上下文，而非自定义错误层级

这是 CLI 而非库——调用者是人，错误最终以一行红字呈现。`anyhow::Result` 加
`with_context` 足够；`thiserror` 仅保留给将来若拆 library 的可能性。
唯一特判的是 `BrokenPipe`（`wots list | head` 场景静默退出 0）。

## 8. 测试跟着行为走，不跟实现走

- 路径映射函数（`compute_dest` / `build_win_path` / `parse_app_arg`）是纯函数，
  表格化穷举边界（尾斜杠、`./` 前缀、多斜杠）；
- 同步状态机用真实临时目录跑端到端场景，包括"第二次检查必须保持状态"这类
  缓存一致性回归；
- 渲染类函数只测"不 panic + 数据结构正确"，不快照比对终端输出。

## 9. 克制的依赖策略

每加一个依赖问一句：标准库或 20 行手写能否替代？`glob` 匹配只用了通配这一
个特性，`shellexpand` 只用 tilde 展开——这类小而专的依赖可以接受；ORM、
框架类的重依赖一律不要。

## 反面教训（历史遗留问题的来源）

早期版本曾同时存在 9 个包类型，其中 `.winlocal` / `.winroaming` /
`.winconfig` 的路径映射逻辑各自复制一份、测试互相污染共享临时目录、死代码
（`scan_windows_for_orphans`）带着 `#[allow(dead_code)]` 存活多个版本。教训：

1. **类型数量与维护成本超线性增长**——砍掉低频类型比留着更省心；
2. **`#[allow(dead_code)]` 是债务标签**，出现即删除或启用；
3. **测试基础设施（temp 目录隔离）和被测代码一样需要 review**。
